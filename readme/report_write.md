下面是当前整理后的“写论文方法论”，后续写入 `my_report.docx` 都按这个执行。

**1. 内容组织**

先写泛用原理，再写本文方法。  
第三章、第四章、第五章都应遵循：

```text
研究背景 / 一般原理
→ 常见建模或算法形式
→ 本文任务中的具体定义
→ 与代码 runtime 主链对应的实现语义
→ 小结
```

原理部分可以泛用化，不必逐行对应代码；但进入“本文方法”后，必须严格对应当前 runtime 主线。

**2. 语义边界**

不能把辅助机制写成主任务语义。

- 避障属于路径生成与执行安全层，不改变 GP、intensity、recency 或综合信息价值场。
- soft responsibility prior 是软分工先验，不是硬分区。
- anomaly_upper_tail 是采集函数变体，不能写成改变目标真实存在概率。
- `kappa_commit`、`alpha_focus`、continuity bonus 等已失效机制，不再作为主线贡献介绍。

**3. 写作语气**

模仿第三章风格：

- 先解释“为什么需要这个概念”；
- 再解释“一般怎么建模”；
- 最后说明“本文如何采用”。
- 少用代码变量堆砌，多用论文语言解释变量含义。
- 但涉及公式、参数、实验设置时必须与代码和数据一致。

**4. 引用策略**

引用不是堆文献，而是服务于本文方法来源。

- GP、核函数、UCB：引用经典 GP 与 GP-UCB 文献。
- 信息型路径规划：引用综述和代表性 IPP 文献。
- anchor 加权中心：引用 coverage control / centroidal Voronoi 思想。
- viewpoint 而非直达热点：引用 next-best-view、coverage sensing、active perception 思想。
- anomaly 变体：引用 anomaly detection IPP、quantile estimation、excursion set、level set estimation 等方向。

引用语言应写成“受……启发”，不要写成“完全采用”。

**5. 公式写法**

公式必须另起一行，居中书写。  
两个以上公式要从“（1）”开始编号。编号位置保持右侧或原模板位置，不随公式主体改变。

正文中明显需要上下标的表达，如：

```text
s_i(x)
d_i(x)
I_t(x)
M_info(x)
```

也应以公式对象或公式格式写入，避免纯文本失去上下标。

**6. 图表写法**

图和表都要有编号与标题，编号和名称之间空 1 个字符间隙，例如：

```text
图4-1 单艇信息驱动安全路径规划总体流程图
表6-1 单艇实验参数设置
```

图表必须与正文一致，不能放入与当前项目主线不符的示意图。  
优先使用真实仿真结果、真实地图、真实 `viz_search.py` 可视化风格，而不是未在项目中出现过的概念图。

**7. 图表选择原则**

论文中不要只放流程图，应组合：

- 场模型可视化图；
- 地图结构图；
- 路径规划流程图；
- anchor/viewpoint 示意图；
- residual_map 顺序分配图；
- 软责任区可视化图；
- 实验结果表；
- 指标对比柱状图或热力图。

图必须服务于解释，不为了“凑图”。

**8. 实验写法**

实验章节先写设置，再写结果，再写解释。

```text
实验目的
→ 实验设置
→ 评价指标
→ 结果表
→ 现象分析
→ 地图结构解释
→ 小结
```

表格必须使用真实结果数据。  
不能把不同地图尺寸、不同 target motion、不同 seed 设置混在一个不公平对比中。

**9. Word 写入规则**

修改 `my_report.docx` 前必须备份，备份文件名带时间戳。  
不要用 PowerShell 内联中文写 docx，避免中文变问号。应使用 UTF-8 Python 脚本，放在：

```text
baseline_GP/results/_temp_run_scripts/
```

写入后必须读取回检查：

- 中文是否正常；
- 标题是否正确；
- 图表编号是否正确；
- 公式是否还在；
- 样式是否被破坏；
- 目录字段是否可更新。

**10. Word 目录与样式规则**

标题目录、公式目录、图目录、表目录应采用“样式 + TOC 字段”。

- 标题目录依赖 `一级标题 / 二级标题 / 三级标题`。
- 公式目录依赖 `公式目录项`。
- 图目录依赖 `图目录项`。
- 表目录依赖 `表目录项`。

自定义样式必须加入快速样式库，否则用户在 Word 样式栏里看不到。  
插入目录字段后必须用 Word 接口刷新，并关闭“显示域代码”。

注意：

```text
Ctrl+A + F9：更新字段
Alt+F9：切换域代码 / 域结果
```

如果看到 `{ TOC ... }`，不是目录没生成，而是 Word 正在显示域代码。

**11. 目录验收**

目录修改后不能只看脚本输出，必须检查：

- 是否存在标题目录；
- 是否存在公式目录；
- 是否存在图目录；
- 是否存在表目录；
- 是否还有“未找到目录项”；
- 是否还有“键入章节标题”模板占位；
- 打开 Word 后是否默认显示目录结果，而不是 `{ TOC ... }`；
- 超链接是否存在。

**12. 工程一致性**

凡是写“本文方法”的地方，最终判断标准是代码 runtime 主链，不是文字设想。

如果论文表述、trace 字段、summary 字段、实验配置和代码行为不一致，以代码当前主线为准修改论文。

**13. Word 脚本定位规则：避免误命中目录**

`python-docx` 读取 `.docx` 时，目录项也是普通段落。目录中的：

```text
6.1 课题总结    40
```

和正文中的：

```text
6.1 课题总结
```

在脚本中都会被读成 `paragraph.text`。由于目录位于正文之前，如果只按文本匹配：

```python
if paragraph.text.strip().startswith("6.1 课题总结"):
    ...
```

脚本会优先命中目录，而不是正文标题。这是最常见的 Word 自动写入错误来源之一。

以后写 Word 脚本时，定位标题必须同时检查：

- 文本内容；
- 段落样式；
- 所在范围。

例如，正文标题应匹配：

```python
if (
    paragraph.text.strip().startswith("6.1 课题总结")
    and paragraph.style.name == "二级标题"
):
    ...
```

目录项通常是：

```text
toc 1
toc 2
toc 3
```

正文标题通常是：

```text
一级标题
二级标题
三级标题
```

更稳妥的做法是先定位正文章标题，再在该范围之后查找子标题：

```python
# 先找到正文中的章标题，跳过目录
if text.startswith("6 总结与展望") and paragraph.style.name == "一级标题":
    chapter_start = idx

# 再只在 chapter_start 之后查找 6.1 / 6.2
if idx > chapter_start and text.startswith("6.1 课题总结") and paragraph.style.name == "二级标题":
    ...
```

如果要替换某一节内容，必须先确认起点和终点都在正文区域内，不能跨过 `参考文献`、`附录` 或目录区域。

安全检查：

- 替换前打印命中的段落 index、style、text；
- 若命中段落样式为 `toc 1 / toc 2 / toc 3`，立即停止；
- 删除或替换段落前，统计待删除段落数量，数量异常时停止；
- 写入后读取回检查目标章节、参考文献、附录是否仍存在。
